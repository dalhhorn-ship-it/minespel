# Factory feedback: minespel, 2026-10-26
Factory started: 2026-10-17
App result: Loved it, 192 ACs, 79 done tasks, 14 fix commits and 24 of 38 friction rows about CI and tests

This file is about the CI, development and testing fixes made in the first 10 days. Founder: "start with fast CI from day one". It follows `2026-10-22.md`; F2, F3 and F5 there were tried here and worked, so this file gives the concrete versions.

## F1: Ship the fast CI workflow in the template
* Area: ci
* Template file: template/.github/workflows/ci.yml, template/scripts/check-scope.sh
* What happened: CI took 6.3 minutes per push, ran twice on pull requests, queued 146 to 148 runs, and the deploy reran the full check. It took four rounds of fixes (decisions 62, 76, 98, 106) to get it fast.
* Evidence: friction 2026-10-19 (two rows), decisions 62 and 76, current `.github/workflows/ci.yml`.
* Proposed change: copy this app's `ci.yml` and `check-scope.sh` into the template. Push runs only (pull_request only for forks), `concurrency` with cancel in progress except on main, WebKit e2e in the `mcr.microsoft.com/playwright` container sharded over 4 jobs (no browser download), content and docs only changes skip e2e, main always runs in full, a `workflow_dispatch` input for the heavy UI review. Deploy on merge to main only after green CI, never a second full check.
* Impact: high
* Confidence: repeated

## F2: A one minute smoke check for developers, the full check once per batch
* Area: skill
* Template file: template/scripts/smoke.sh, template/.claude/agents/developer.md, template/scripts/verify.sh, template/docs/FACTORY.md
* What happened: every developer ran the full `check.sh` (all unit tests, all e2e) for every task. Parallel developers loaded the machine and caused timeouts that looked like failures.
* Evidence: decision 107, friction 2026-10-17 (T27 timeout under parallel load), 2026-10-19 (unit flakes with three developers), 2026-10-26 (context loss spec fails at 8 workers on 4 cores).
* Proposed change: add `smoke.sh` (lint, types, `vitest related` on changed files, build, dist check, 3 core e2e specs plus changed specs on one iPad size). Developers run it. `verify.sh task` runs the full check once per batch. Playwright `workers` never above the core count.
* Impact: high
* Confidence: repeated

## F3: E2e tests wait on state, never on the clock
* Area: template
* Template file: template/tests/e2e/helpers.ts, template/eslint.config.js, template/.claude/agents/developer.md, template/.claude/agents/qa.md
* What happened: 8 red CI rounds came from tests that read state right after a tap, slept a fixed 150 ms, read physics after wall time, or trusted an e2e hook that turned ready before the app's ready gate. Each time the app was right.
* Evidence: friction 2026-10-17 (egg), 2026-10-18 (three rows), 2026-10-19 (unit sleeps), 2026-10-23 (hook race, physics on a slow runner), decision 107.
* Proposed change: ship helpers from day one: `waitFrames(n)` that steps the game loop, `expect.poll` wrappers, and e2e hooks that resolve only after the boot ready gate. A lint rule bans `waitForTimeout` and `setTimeout` sleeps in tests (allow with a comment for "a paused world stays still"). In unit tests use `vi.waitFor`. Physics tests step frames, not milliseconds. Say this in the developer and qa prompts.
* Impact: high
* Confidence: repeated

## F4: Browser tests must run in the agent's own sandbox on day one
* Area: stack
* Template file: template/scripts/check.sh, template/scripts/smoke.sh, template/docs/PLATFORM.md, template/.claude/skills/factory/SKILL.md
* What happened: for 9 days WebKit could not install in the cloud sandbox, so e2e mistakes (guessed selectors, races) were found only in CI. A Chromium fallback helped but has its own red tests (exam clock, jump height) that WebKit passes.
* Evidence: friction 2026-10-17, 2026-10-19 (two rows), 2026-10-23 (local Chromium), decision 100, decision 107.
* Proposed change: the first `/factory` step checks that `npx playwright test` runs WebKit in the sandbox and, if not, asks the founder once to allow the Playwright hosts. `check.sh` and `smoke.sh` pick WebKit when installed, else Chromium with a loud note that CI on WebKit is the truth. PLATFORM.md lists known Linux WebKit gaps (iOS only CSS like `-webkit-touch-callout` is dropped from computed style; test the shipped rule).
* Impact: high
* Confidence: repeated

## F5: "Flake" is not a root cause
* Area: agent
* Template file: template/.claude/agents/qa.md, template/.claude/agents/developer.md, template/docs/FACTORY.md
* What happened: a real regression (pause hook race) was first taken for a load flake. Other failures were real load problems in fake clock tests. Main CI went red after a merge and nobody looked for a day.
* Evidence: friction 2026-10-23 (three rows).
* Proposed change: a triage rule in the prompts: before calling a test flaky, run it on the commit before the change and with 1 worker. If it fails there too, it is a load or test bug, logged as its own task. The operator checks main CI after every merge.
* Impact: medium
* Confidence: repeated

## F6: Parallel developers in worktrees need the branch and their own port
* Area: skill
* Template file: template/.claude/skills/build/SKILL.md, template/playwright.config.ts
* What happened: agent worktrees start from `main`, not the working branch, so two developers lacked `smoke.sh` and `E2E_PORT`. Two e2e servers on one port clashed, and one spec hardcoded port 4173.
* Evidence: friction 2026-10-26 (R2 build), decision 108, commits for AC189 and `E2E_PORT`.
* Proposed change: the build skill tells every developer in a worktree to merge the working branch first. `playwright.config.ts` reads `E2E_PORT` for the web server and `baseURL`; specs use `baseURL`, never a literal port.
* Impact: medium
* Confidence: once

## F7: The heavy UI review is not part of normal runs
* Area: ci
* Template file: template/playwright.config.ts, template/package.json, template/.claude/agents/kid-ui-reviewer.md
* What happened: `ui-review.spec.ts` (every screen on every iPad size) was 86% of e2e time on every push.
* Evidence: friction 2026-10-19, decision 106: 285 to 144 e2e tests per run.

* Impact: medium
* Confidence: once
