### v3 Dino's veilig (0.6.0)

**Status:** next. Picked by the founder on 2026-11-06 (decisions 90 and 119). Ships as 0.6.0, after v11 Dorp (0.5.0) and before v6 Wat heb ik geleerd (0.7.0, which gets its own signoff). The section was drafted in `docs/BACKLOG.md` on 2026-10-24.

**Goal:** "My world, my dinos and my points are safe. Even on a wiped or new iPad, papa or mama can bring them back."

**Why:** Safari can wipe the storage of a site and iOS can kill the app. The home screen app and a Safari tab keep separate saves (decision 72). Today there is no way back after a wipe, and the kid now has a big herd, rare blocks and villages to lose. Alles wissen only makes sense once a backup exists. A parent also has no way to end a learning break today: the button "Pauze nu beëindigen" is in the parent area, but a break has no lock (decision 53), so it can never be tapped. The founder chose a small lock on the break, only to end it (V3-1, decision 119).

**In:**
1. **Backup maken** under Import en export (4.15): one `.json` file with everything except the pincode and the gate lockout, with the file header (app name, format version, date). It holds the found rare blocks, the villager cooldown and the villager who asked last from v11. It never holds the kept copy of the 0.4.0 world record. The file leaves only through the share sheet or the new view fallback. The app remembers the date of the last backup.
2. **Backup terugzetten:** the parent picks a file. It is checked in full, then a confirm shows, then all data is replaced in one safe write. A broken, wrong, too big or newer file changes nothing. The pincode stays as it is on this iPad. After the restore the app shows the restored world.
3. **Alles wissen** (4.17): two confirms with different words, then everything is deleted, also the pincode, and a new game starts.
4. **Volume** 0 to 100, default 70, and the **app version** at the bottom of Instellingen (4.17).
5. **A lock on the learning break, only to end it** (decision 119). It works like the exam lock (decision 61, AC155 to AC158): small and grey in the top right corner, it opens the pin pad. After the right pincode a small parent view offers only "Pauze nu beëindigen" and "Terug naar de pauze". No other parent function can be reached from it. Ending the break works as AC95 says and play resumes with the play timer at the full interval, as after any break (AC36). The lock shows on the questions, lessons and teach moments of a timed break, a Nu oefenen break and a break from Pauze nu starten, not on the summary and not in Extra oefenen.
6. **Tests** for Pauze nu starten, Pauze nu beëindigen and Wereld opnieuw beginnen, which v1 already has. Bugs they find are fixed in this release.
7. **The kept copy of the old world record** from v11 (v11 In item 2) is deleted when 0.6.0 first opens a save. The world itself does not change.
8. **Version 0.6.0** and a kid readable entry in `CHANGELOG.md`. The 0.6.0 entry also takes in what is live on `main` but listed under Unreleased (decisions 111 to 116). That part is a version matter only and gets no new criteria here.

**Out:**
* The backup reminder after 30 days, the broken save screen, persistent storage and the first start flow (v4).
* Module import and export (dropped, decision 79).
* Automatic, cloud or server backups, and any sync between iPads or between the home screen app and a Safari tab.
* The save on refresh fix (on hold, decision 72).
* A lock on Extra oefenen (it has Stoppen for the kid) or on the break summary.
* New PRD text or criteria for the Unreleased features of decisions 111 to 116.

**Kid safety.** Backups are made and restored only in the parent area, behind the gate. They hold only game data (dino names included), no real name, age, photo, location or contact data, no pincode and no lockout. The file name is only the app name and the date. A backup never leaves the iPad on its own: no upload, no server, no network request, only the parent's own share sheet. A restored file is checked in full and its text shows only as plain text, never as a link or a script. The break lock is one more door to the parent gate, with the same pincode and shared lockout; behind it only the break can be ended, so a kid who guesses nothing can change nothing. Section 9 holds as updated in this signoff.

**Acceptance criteria.** All criteria in section 7 still hold. v3 completes these existing ones: AC87, AC93 (the Volume part), AC94 (tests), AC95 (tests, reached through the break lock), AC130, AC131, AC133, AC135 and AC152 (the Alles wissen and restore part). AC87 also covers the found rare blocks and the villager cooldown. New for v3:

* **AC192 (v3):** Given Instellingen, then a Volume setting from 0 to 100 shows, set to 70 on a new game. Given Volume 0, then no sound effect is heard. Given Volume 40, then the next sound effect plays at 40 percent of full loudness. Given the parent sets 40 and the app is closed and reopened, then Volume is still 40. Given Geluidseffecten uit, then no effect plays at any Volume.
* **AC193 (v3):** Given "Alles wissen", then a first confirm and a second confirm with different words show, and "Annuleren" at either step changes nothing. Given both confirms, then all data and the pincode are gone, a new game shows as in AC12, and the next tap on the lock asks the grown up question before a new pincode (decision 52).
* **AC194 (v3):** Given "Backup maken", then exactly one file is made, named `dino-blokwereld-backup-JJJJ-MM-DD.json` with the date of today. It holds no pincode, no pincode hash and no gate lockout, and no copy of the 0.4.0 world record. The date of this backup is saved. Making the backup sends no network request (automated). Given a save that still holds the kept copy of the 0.4.0 world record, when 0.6.0 opens it, then the copy is deleted and every block of the world is as before.
* **AC195 (v3):** Given a file to restore that is not JSON, is over 20 MB, or holds a value outside the save rules (a dino name over 12 characters or with characters not on the app keyboard, such as `<b>Pip</b>` or `https://x.nl`, negative points, more shop dinos than the shop allows (25, decision 111) or more than 10 chickens), when the parent restores it, then a friendly Dutch message shows and nothing changes. No text from a backup ever shows as a link or runs as a script.
* **AC196 (v3):** Given no break and no exam running, when the parent taps "Pauze nu starten", then the parent area closes and a learning break starts right away with the timed break rules. When the kid finishes it and taps "Terug naar de wereld", then play resumes with the play timer at the full interval.
* **AC197 (v3):** Given a valid backup, when the parent taps "Backup terugzetten" and picks it, then a confirm "Alles op deze iPad wordt vervangen door de backup van [datum]" shows with "Terugzetten" and "Annuleren". "Annuleren" changes nothing. Given a restore that is killed halfway (simulated), when the app reopens, then it holds all the old data or all the new data, never a mix.
* **AC198 (v3):** Given the v3 build, then `package.json` has version 0.6.0, Instellingen shows 0.6.0 at the bottom, and `CHANGELOG.md` has a 0.6.0 entry in kid readable words that says papa or mama can keep your world and dinos safe in a backup. The entries that were under Unreleased are part of the 0.6.0 entry.
* **AC199 (v3):** Given a learning break runs (timed, Nu oefenen or started with Pauze nu starten) with a question, lesson or teach moment on screen, then a small grey lock shows in the top right corner, with a tap area of at least 44 x 44 points fully inside the safe area, not over an answer button or the number pad. When it is tapped, then the pin pad of the parent gate opens. When the right pincode is typed, then a parent view shows with only "Pauze nu beëindigen" and "Terug naar de pauze", and no settings, content, results or backup. Given "Pauze nu beëindigen", then the break ends as in AC95 and the kid is in the world with the play timer at the full interval. Given "Terug" on the pin pad or "Terug naar de pauze", then the break shows the same question with the same typed answer. Given the kid does not know the pincode, then the break cannot be ended: 3 wrong codes block the gate for 1 minute with the shared lockout of AC74, and the break stays on the same question. Given the break summary, Extra oefenen or the world, then this lock does not show (the world keeps its own lock, the exam its own, AC155).

**Check before shipping:** on the founder's iPad, on the HTTPS address (a test deploy is a founder action), from the home screen icon: make a backup to Bestanden, change something, restore it and see the old world back. Then in a Safari tab with empty storage, set a pincode through the lock, restore the same file and see the world, dinos, rare blocks and points appear. Turn Volume down and up. Start a break, tap its lock, type the pincode, end the break and see the world with a full countdown. Hand the iPad to the kid during a break and see that the lock does not help without the pincode.
